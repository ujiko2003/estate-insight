Estate Insight

국토교통부 아파트 매매 실거래가 공공데이터를 주기적으로 수집해 지도 기반으로 검색·통계를 제공하는 서비스. 백엔드 이직 포트폴리오를 목적으로, 기능의 개수보다 "문제 → 선택 → 결과"를 코드와 기록으로 남기는 것이 이 프로젝트의 진짜 산출물이다.

서비스 이용 방법

개발자가 이 서비스를 어떻게 호출하게 되는가

MVP의 핵심 조회 기능은 네 가지(02~05) — 전부 읽기 전용 REST API이고, 응답은 항상 엔티티가 아닌 record(DTO)다. 01 지역 조회는 그 네 기능이 다루는 수집 대상 목록으로, 먼저 동작을 확인한 보조 기능이다. 아래는 1-8 단계에서 구현될 API 계약 초안 — 예정 표시가 없는 것만 지금 실제로 동작한다.

01

지역 조회 완료

수집 대상 시군구 목록. 실거래 데이터 자체를 조회하는 기능은 아래 02~05 — 1-8에서 붙는다.

GET /api/regions → [{"sggCode":"11680","sidoName":"서울특별시","sggName":"강남구","isActive":true}, ...]
02

실거래 조건 검색 예정 · 1-8

시군구 코드(LAWD_CD 체계) · 계약 기간 · 가격대로 거래 내역을 좁힌다.

GET /api/trades?sgg=11680&from=2026-01&to=2026-06&minPrice=80000&maxPrice=150000
03

지도 검색 예정 · 1-8

지도 화면 영역(bbox)이나 중심점 반경 N km 안의 거래를 PostGIS로 조회한다 (ST_MakeEnvelope / ST_DWithin).

GET /api/trades/map?bbox=127.02,37.49,127.06,37.52 GET /api/trades/map?lat=37.50&lng=127.04&radiusKm=1.5
04

단지별 가격 추이 예정 · 1-8

하나의 아파트 단지(aptSeq)가 월별로 평균 얼마에 거래됐는지 추이를 보여준다.

GET /api/complexes/11680-2246/price-trend → [{"month":"2026-04","avgPrice":182000}, {"month":"2026-05","avgPrice":186500}, ...]
05

시군구 통계 예정 · 1-8

시군구 단위 평균 평당가와 거래량 — 해제된 거래(is_cancelled)는 제외.

GET /api/stats/region/11680 → {"sggCode":"11680","avgPricePerPyeong":8820,"tradeCount":412}
목표 아키텍처

2단계 배포가 끝났을 때의 모습

지금은 Docker Compose로 Postgres·Redis만 로컬에 띄워놓고 api·batch를 호스트에서 직접 실행하는 상태다. 아래는 2단계(AWS 배포)까지 끝났을 때의 최종 형태 — 조회 경로(위)와 수집 경로(아래)가 같은 RDS를 공유하는 구조다.

모듈 구조

왜 Gradle 멀티모듈로 쪼갰는가

api와 batch는 배포 단위가 다르다 — api는 상주 서버(ECS Service), batch는 실행 후 종료(ECS Task). 그래서 "배포 단위가 다르면 모듈도 분리한다"는 기준으로 쪼갰고, core는 둘 다 쓰는 도메인(엔티티·리포지토리)과 Flyway 마이그레이션을 들고 있다.

DB 설계

5개 테이블, Flyway로 버전 관리

PostgreSQL 16 + PostGIS. 스키마는 전부 Flyway 마이그레이션(V1~V4, core 모듈 소유)으로만 바뀐다 — Hibernate의 ddl-auto는 validate로 고정해서 자동 생성을 막아둔다.

테이블핵심
regionPK sgg_code — 국토부 API의 LAWD_CD 그 자체. is_active로 수집 대상 지정 (MVP는 강남구 11680만 true)
apt_complexPK는 API의 aptSeq. 좌표는 GEOGRAPHY(POINT,4326) + GIST 인덱스
apt_tradeAPI에 고유 ID가 없어 trade_key(자연키 SHA-256, UNIQUE)로 upsert. 금액은 만원 단위 INTEGER
geocode_cache정규화 주소가 PK. 실패(NOT_FOUND)도 저장해 API 호출 한도를 아낌
ingest_statusPK (sgg_code, deal_ym) — 지역×월 단위 수집 상태, 중단 후 이어받기용
  • trade_key에 해제 여부는 넣지 않는다. 같은 거래가 나중에 '해제' 표시로 다시 들어오는데, 해제 여부를 키에 포함하면 중복으로 쌓인다 — 빼야 upsert로 상태만 바뀐다.
  • GEOGRAPHY를 고른 이유. 미터 단위 반경 검색(ST_DWithin)이 인덱스를 타며 바로 된다. GEOMETRY와의 실행계획 비교는 3단계(성능 튜닝)에서.
  • 통계용 인덱스는 부분 인덱스. WHERE is_cancelled = FALSE — 통계 조회가 거의 전부 해제 거래를 빼고 보기 때문.
