# 1-5 실거래가 API 클라이언트 (진행 중)

금액 변환과 단위 테스트는 아직 하지 않았다.

## 1. 호출과 파싱을 나눌 것인가

**문제**
API 응답은 XML이다. 호출하면서 바로 객체로 받을 수도 있고, 문자열로 받은 뒤 따로 변환할 수도 있다.

**선택지**
- (A) `RestClient`로 호출하면서 XML을 객체로 바로 변환
- (B) 호출 부품은 XML 원본 문자열을 반환하고, 파싱 부품이 객체로 변환

**결정**
(B). `AptTradeApiClient`와 `AptTradeXmlParser`로 나눈다.

**이유**
- 1-6에서 원본 응답을 파일로 저장해야 한다. 원본이 있으면 파싱 버그를 고칠 때 API를 다시 호출하지 않아도 된다.
- 파서는 문자열만 받으므로 네트워크와 인증키 없이 테스트할 수 있다.
- 네트워크·인증 문제와 데이터 형식 문제가 서로 다른 부품에서 드러난다.

**결과 수치**
- 파서에 샘플 XML 10종을 넣어 정상 2종, 빈 목록 3종, 비정상 응답 4종, XML이 아닌 입력 1종의 동작을 네트워크 없이 확인했다.

## 2. 이미 인코딩된 인증키를 어떻게 보낼 것인가

**문제**
포털의 일반 인증키에는 `%2B`, `%3D` 같은 인코딩 문자가 들어 있다. `RestClient`에 문자열 URI를 넘기면 값이 다시 인코딩되어(`%`가 `%25`로 변환) 인증에 실패할 수 있다.

**선택지**
- (A) 문자열로 URI를 넘겨 `RestClient`가 인코딩하게 한다.
- (B) Decoding 키를 쓰고 `RestClient`가 인코딩하게 한다.
- (C) `UriComponentsBuilder.build(true)`로 인코딩이 끝난 `URI` 객체를 만들어 넘긴다.

**결정**
(C).

**이유**
(A)는 이중 인코딩이 생긴다. (C)는 포털에서 받은 키를 그대로 환경변수에 넣어 쓸 수 있고, "이미 인코딩된 값"이라는 의도가 코드에 드러난다.

**결과 수치**
- `./gradlew :batch:bootRun --args='runDate=2026-12-05'`로 실제 호출: `resultCode` `000`, Step 실행 224ms.
- URI에 인증키가 포함되므로 URI 전체를 로그로 남기지 않는다.

## 3. 응답을 어떤 모양으로 받을 것인가

**문제**
응답에는 값 없음이 공백 한 칸으로 오거나(`<aptDong> </aptDong>`), 앞자리 0이 의미 있는 값(`<bubun>0003</bubun>`), 쉼표가 든 금액(`335,000`)이 섞여 있다. XML 계층도 깊고 중간 값이 null일 수 있다.

**선택지**
- (A) JPA 엔티티로 바로 변환
- (B) `Item`을 숫자·날짜 타입으로 선언
- (C) XML 모양 record(`AptTradeResponse`, `Item` 필드는 전부 `String`)와, 검사를 마친 결과 record(`AptTradePage`)로 분리

**결정**
(C). `Item` 필드는 25개다.

**이유**
- XML 구조와 DB 구조는 다르다. 예를 들어 `dealYear`, `dealMonth`, `dealDay`는 DB에서 `deal_date` 하나가 된다.
- 전부 `String`으로 받으면 원본 값이 유지되고, 변환 규칙을 한곳에 모을 수 있다.
- `AptTradePage`를 쓰는 쪽은 XML 구조와 null 처리를 몰라도 된다.

**결과 수치**
- 강남구 2026년 9월 응답의 `totalCount`: 125건.

## 4. 비정상 응답을 어떻게 구분할 것인가

**문제**
공공 API의 인증 실패 응답은 성공 응답과 XML 구조 자체가 다르다(`<OpenAPI_ServiceResponse><cmmMsgHeader>...`). Jackson은 이 XML을 받아도 예외를 내지 않고 `header`와 `body`가 null인 객체를 만든다.

**선택지**
- (A) XML 변환 예외에만 의존
- (B) 변환 후 `header`, `resultCode`, `body`, `totalCount`를 직접 검사

**결정**
(B). 비정상이면 `IllegalStateException`을 던지고, 거래가 없는 정상 응답은 빈 목록으로 처리한다.

**이유**
(A)는 인증 실패를 거래 0건으로 착각하거나 원인을 알 수 없는 NPE로 끝난다. 수집이 조용히 비어 버리는 상황을 막아야 한다.

**결과 수치**
- `resultCode` 오류, 접근거부, `body` 누락, `totalCount` 누락 4종 모두 `IllegalStateException`으로 처리됨을 확인했다.

## 남은 문제

- 금액 변환과 단위 테스트, 실제 응답 전체를 파서에 넣는 확인.
- 거래 0건인 달의 실제 응답 모양은 아직 확인하지 않았다.
- `apt_complex.umd_code`는 `CHAR(3)`인데 실제 `umdCd`는 `10600`처럼 5자리다. 1-6 전에 결정이 필요하다.
- `aptDong` 등의 공백 한 칸은 `trade_key` 생성 시 trim 규칙을 일관되게 적용해야 한다.
- `RestClient` 타임아웃은 1-6에서 설정한다.
